# RGB555 host display contract

## Status and scope

**Project compatibility contract, not a hardware LCD measurement.** This describes the observable native software display output in the absence of master brightness. The original project comment explicitly compared the native-size colour path with a reference emulator (DeSmuME); the precise historical origin of the conversion is unresolved. The table below preserves that reference-informed project behavior; it is not an independently measured emulator or hardware result, nor evidence of independent authorship. The host's eight-bit output policy is not specified by the DS palette layout.

[GBATEK's LCD palette documentation](https://problemkaputt.de/gbatek.htm#lcdcolorpalettes) describes 5-bit red, green and blue components. RGB555 input bits 0–4, 5–9 and 10–14 are red, green and blue; bit 15 is ignored for this LCDC display case. A host pixel is `0xFFRRGGBB`, with each channel obtained by integer floor of `255*c/31`. Alpha is 255.

For the eight-lane output interface, each lane independently takes a channel
`c` in 0–31 and brightness factor `f` in 0–16. Mode 0 leaves `c` unchanged;
mode 1 yields `c + floor((31-c)*f/16)`; mode 2 yields
`c - floor(c*f/16)`. Apply the same `floor(255*c/31)` expansion to the
result of that mode for each lane. Lane ordering is unchanged.

The ROM-free `rgb555_exhaustive` test writes all 32,768 RGB555 words with both values of bit 15 to LCDC VRAM and checks all 65,536 host pixels against the table. The existing `output_reference` also exercises RGB555 across master-brightness register values. These are project regression contracts, not hardware conformance measurements.
