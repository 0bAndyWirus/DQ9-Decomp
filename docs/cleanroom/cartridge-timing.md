# Cartridge first-word timing contract

This specifies the observable compatibility behavior of the current runtime, not a hardware timing specification. The first-word delay is reference-emulator-derived compatibility behavior (DeSmuME); it has not been established here by an independent hardware measurement. The polling and completion behavior below describes the runtime's contract, not a claim that every event matches that emulator or physical hardware.

## Inputs and time unit

Start a transfer by writing ROMCTRL (`0x040001a4`) with bit 31 set. Time is counted in 33 MHz machine ticks advanced after that write. Let `G` be ROMCTRL bits 0–12 and `C` be 5 if bit 27 is clear or 8 if bit 27 is set. For a nonempty transfer, the first data-ready event occurs after exactly `D = (8 + G) * C + 4` ticks. The second gap field (bits 16–21) does not affect this first-word delay.

| Bit 27 | G = 0 | G = 1 | G = 8191 |
|---|---:|---:|---:|
| 0 | 44 | 49 | 40999 |
| 1 | 68 | 76 | 65596 |

For ordinary transfers, block size codes 0 through 7 in bits 24–26 select respectively 0, 512, 1024, 2048, 4096, 8192, 16384 and 4 bytes. Chip-ID commands `0x90` and `0xb8` instead produce four bytes regardless of the block code; command `0x3c` produces no data regardless of the block code. This contract does not specify cryptographic command behavior.

## Observable events

* At the start of a nonempty transfer, BUSY (ROMCTRL bit 31) is set, DATA_READY (bit 23) is clear, and reading the data port (`0x04100010`) returns zero without consuming a byte.
* After any total of fewer than `D` ticks, BUSY remains set, DATA_READY remains clear, and no data-ready or completion event has occurred. At tick `D`, DATA_READY is set and one data-ready event is delivered. Advancing time in multiple increments gives the same boundary.
* While data remains unread, BUSY and DATA_READY remain set. Additional time does not generate another data-ready event. Reads consume data in little-endian byte order; successive words may be read without advancing time. There is no additional per-word delay in this contract.
* Consuming the final byte clears BUSY and DATA_READY. If the cartridge transfer interrupt is enabled in AUXSPICNT, completion raises the transfer interrupt (IF bit 19 on the Slot-1 owner). Otherwise it does not. The completion event is not repeated merely by advancing time. A data-ready event may instead trigger an enabled cartridge DMA, which can consume data at the readiness boundary.
* An empty transfer completes during the start write: BUSY and DATA_READY are clear, no data-ready event occurs, and the enabled completion interrupt is raised immediately. The gap and clock fields do not delay this completion.

The timing tests use generated byte-pattern fixtures, not game ROM data. The peripheral cases exercise both clock settings, eight first-gap values and all seven nonzero block codes; the core cases additionally check the interrupt and bus-owner integration. These tests define compatibility expectations; they are not independent measurements of hardware.
